A500 Copper launch and line BZERO follow-up

Measurements use a PAL A500 with 512 KiB chip and 512 KiB slow RAM, ECS Agnus and OCS Denise, with One ROM live ROM replacement and checksum-protected USB result collection. Each run backs up the current live ROM, verifies the test image after writing it, and restores and verifies that run’s backup before releasing reset. ROM images and raw captures remain local assets.

Toni Wilen’s EAB observations motivated the Copper-start and register-handoff controls: post 1426048 describes possible Copper/blitter start inhibition, and post 1422393 describes register updates after BBUSY clears while the last destination write is pending. These are hypotheses to test, not substitutes for measurements.

Copper WAIT controls¶

The Copper starts a 16-word D-only or A-to-D blit and executes one or two already-eligible BFD-clear WAITs before requesting COPER. The CPU executes ROM NOPs or chip-memory reads without a loop branch or DMACONR polling. The IRQ handler’s first VHPOSR read is an observation of the complete path, not a direct timestamp of the Copper WAIT edge.

All 1,024 rows complete successfully on each platform with matching marker count, destination data and BBUSY-clear readback. Excluding horizontal positions 0/1, which straddle VHPOSR’s pipelined line wrap, and requiring equal launch timestamps gives:

This isolates a blit-dependent path; it does not justify adding a blanket IRQ delay or establish the reported start-inhibition bug.

The revised finish sweep keeps that sample in a register and writes BLTSIZE in the next instruction. It varies widths 1/4/8/16, one/two WAITs, CPU ROM NOPs/chip reads, BLTPRI, launch padding and phase, without display DMA (2,048 trials). Its source fingerprint is 2f6f69331db2e4c964d333f0aab48c5054194f6eaec4a9cef658b7fc59106c7a.

All revised-sweep rows complete with expected destination words and the IRQ after CPU BLTSIZE. Requiring equal launch observations gives 374 baseline Copperline comparisons: 326 exact, 39 two clocks late and nine eight clocks late. The one-word controls are all exact; most differences occur with 8/16-word blits. WinUAE matches all 396 rows whose launch observations match hardware. Pairwise populations differ because actual launch phases differ. These CPU-launch residuals have the opposite sign to the Copper-launch median; a universal start or IRQ delay would be unjustified.

Captures: rom-amiga500-copper-wait-finish-sweep-v2-run1/capture and the corresponding Copperline/WinUAE folders. The earlier finish-sweep archive without v2 is excluded: its late launch gate allowed the Copper request to precede CPU BLTSIZE in some rows.

Next measure BBUSY directly around Copper BLTSIZE with one status read per phase, followed by an adjacent-read control. Record actual beam brackets and include matched no-blit lists. CPU custom-register reads can themselves perturb bus arbitration, so an eight-read train alone cannot establish an unobserved launch edge. Separate onset, completion, Copper wake and CPU IRQ observation before changing any of those delays.

CPU register-handoff controls¶

All 2,304 A500 records complete without timeout. The observed immediate last-D read and both settled destination endpoints equal the expected FFFF (D-only and ABCD) or AAAA (A-to-D) on all three platforms. No stale final word is observed by this polling sequence. This confirms the tested update sequence; it does not prove that software reads the pending-write interval itself.

Launch beam timestamps match all 2,304 descriptors across the three platforms. With extra display/Copper DMA disabled, all 576 handoff beam observations also match A500 exactly. Four/six-plane contention exposes further Copperline timing differences. WinUAE matches every clean four-plane and six-plane handoff timestamp; the six-plane-plus-Copper-burst workload has 44 nonmatching clean observations out of 548. It therefore must not be treated as hardware truth for all contention cases. The handoff timestamp is measured after polling, a memory read and BLTCON0 write; poll-loop quantization can magnify a small preceding difference.

This kind repurposes raw result offsets: +14 first-clear DMACONR, +16 immediate last-D read, +18 postwrite DMACONR, +20/+22 handoff beam reads, +24/+26 final first/last D, +28 INTREQR, +30 settled beam, +32 status. Generic CSV column names such as counter, icr or saved_pc do not describe those fields.

Capture: rom-amiga500-blitter-handoff-kind49-run1/capture; packet SHA-256 480f5177aea788d870b4714d49d6b6465a9e9f8139e6c75941417cb4aa7a0b3b.

Line BZERO one-hot controls¶

All 1,536 records have identical launch/read/end beam observations and final destination words on A500, baseline Copperline and WinUAE. Eight repeats of each case are identical. Nonzero-B controls verify the effective A word: the first pixel writes ADAT >> ASHIFT, and the second writes the next bit position. Zero-B controls write zero to both destinations.

Only the two-pixel, zero-B wrap cases differ. With target n selecting ADAT = 0x8000 >> n, A500 leaves BZERO set for:

The unexplained exceptions correspond to effective A positions 13 and 11. Do not encode that incidence map as an unexplained constant. Next controls must distinguish intermediate B/C inputs, minterm evaluation and flag reduction using other minterms, multi-bit A inputs and non-wrap B shifts.

Minterm and non-wrap controls¶

The 2,048-row truth-control archive has source fingerprint feb59528cda4d4797efdb5776d9d385b6d34948360074698c5748b892f489621. It crosses eight A patterns, minterms 00/FF/F0/CC/33/AA/40/CA, zero/all-one register B data, B shifts 0/1 and eight repeats. C DMA remains enabled from zeroed memory; B DMA is disabled. The original observer is unchanged.

Every beam observation and both destination words match on all three platforms, and every repeat is identical. At BSHIFT=0 with B=0, hardware sets BZERO for minterms 40 and CA only when A is 2000, 0800 or 2800; adding bit 0 (A=2801) clears it. Direct-A minterm F0 clears BZERO for all nonzero A, so the hardware does detect those bits in the ordinary pixel calculation. Minterm CC clears BZERO on hardware, as in Copperline; WinUAE keeps it set. At BSHIFT=1, the disputed zero-output cases keep BZERO set on all platforms. These controls narrow the exception to the inter-pixel wrap evaluation. They still do not independently measure the intermediate B word or establish why the effective A-mask has these exceptions.

Capture: rom-amiga500-line-a-bit-truth-control-run1/capture; packet SHA-256 d767ef553a221a0ace394153d993fb59f1cc0369a11a43f292d4c20d91c20304. For both kind48 modes, raw offsets +20..+34 are eight DMACONR words, including offset +32; the generic decoder’s status field is therefore a flag sample, not a timeout status. Completion is verified by the packet’s complete flag, checksum and descriptor count.

Retained B data and shifter carry¶

Separate history controls prime B through CPU writes, normal B DMA, or line B DMA, then run a target with USEB clear. They distinguish raw BLTBDAT from the B hold consumed by a normal-mode minterm. Target writes to BLTBDAT are made before clearing CON1, after clearing it, or omitted. The preceding line can therefore expose both its retained hold and the raw-word carry used by a later CPU write.

The normal-history control separately exposed 16 remaining records where line B DMA must preserve carry for a later CPU BLTBDAT write. Both checks were necessary before accepting the final model.

No additional timing delay or serialized state field is needed. This data-retention correction does not resolve the independent inter-pixel BZERO or Copper WAIT timing residuals.

Scope qualification¶

The MHO98 accepts 50M acquisition depth at 2 ms/div and exports 12.5M digital samples, about 25 ms at a CPU-clock-derived sample interval near 2 ns. The RG03 LA time-increment header still reports 0.5 ns and cannot be trusted. This time calibration uses nominal PAL CPU frequency, not an independent frequency reference. Some deep captures have no qualified custom accesses or the selected trigger edge and are excluded from timing evidence. One overlaps the live-ROM helper’s startup/reset interval; a later normal Kickstart deep capture also lacks the selected edge, so reset does not explain every case. A subsequent normal Kickstart capture has varied address/control signals and REGEN activity. Require actual qualified bus windows before interpreting any future scope recording; a reported STOP state alone is insufficient.

Copper start pipeline, 19 October follow-up¶

Model the Copper BLTSIZE/BLTSIZH start path with its busy latch one DMA slot (two colour clocks) after data fetch, and engine progression/zero reset two slots (four clocks) after fetch. This separation fits the measured observations; CPU writes enter through the existing completed-cycle path. Keep CPU custom-read sampling unchanged: moving it globally repaired Copper observations but broke CPU controls. The pending start pipeline advances even when blitter DMA is disabled, reserves no memory slots, participates in slot/deadline predictions, and is retained in snapshots. Forced synchronous completion drains it before evaluating the blit.

A500 pressure, onset and completion-marker probes distinguish these phases. A single four-clock delay made completion agree but delayed busy assertion; a two-clock delay still completed early. Separating the busy and engine stages repairs the repeated early BBUSY/BFD completion-marker family. This is a measured start-path correction, not a change to the body or terminal sequencer. Evidence, ROM fingerprints, versioned packets, rejected candidates and detailed validation live in the sibling repository at amiga-hardware-probes/docs/bus-pressure-2026-10-19.md and references/bus-{pressure,onset,phase-completion}*.

One onset observation of initial BZERO remains different before the first nonzero blit. The probe does not precondition that accumulator, so warm hardware reset and emulator construction cannot be assumed to establish the same state. A deliberately primed probe is needed before inferring reset behavior. Existing CPU register-handoff discrepancies also remain a separate investigation.
