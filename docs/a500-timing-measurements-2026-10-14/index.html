A500 timing measurements and remaining work, 14-15 October 2026

Latest line-mode follow-up: 16 October digital bus measurements. Several older C-dependent flag mismatches no longer reproduce after a cold power cycle and installation of the probes; the cause is not yet isolated. New kind33 captures retain repeatable shift/B-DMA BZERO differences.

Scope and method¶

Measurements used One ROM on the owner’s PAL A500: 512 KiB chip RAM, 512 KiB slow RAM, ECS Agnus 8372A (raw VPOSR $a000/$a001), OCS Denise (raw ID $ffff). One ROM Fire-40-A ran firmware 0.8.0, USB plugin 0.3.2 and host-control 0.1.6, with SEL_C resetting the 68000. Timed observations were collected into RAM before RBCP USB transfer. Captures validate their additive checksum, source ID, trial descriptors, timeouts and skipped rows. No RBCP command ran inside a timed kernel. ROMs, firmware and captures remain local assets.

WinUAE 6.0.3 used A500 Best Compatibility, PAL, ECS Agnus, a cycle-exact 68000, cycle-exact memory/blitter, matching memory sizes and no JIT. Copperline used the same machine configuration in deterministic headless runs. ROM kernels align horizontal launch phase and record the actual full launch beam; the IRQ controls also rendezvous at line 64 before launching. Elapsed beam time is 227 * deltaV + deltaH, with unsafe line-edge/wrap samples excluded. Same descriptor numbers alone are insufficient evidence of the same phase.

The original Kickstart was restored after the last hardware measurement. A 524,288-byte live-ROM read has SHA-256 9797dfe08af1e48271528411a41eda20fb03ee3cf387e610ce50eedfb0c457eb, identical to the pre-measurement backup. No capture establishes timing for every OCS/ECS revision, AGA, faster CPU, NTSC mode or arbitrary contention pattern.

Across both BLTPRI settings the three primary aligned observers provide 20,736 exact masked-state and elapsed-time matches for the corrected blitter sequencer. Those masks intentionally observe BBUSY, BLIT request or memory; they do not establish correctness of every other bit in DMACONR/INTREQR. The additional BZERO sweep tests the defined DMACONR mask $67ff explicitly.

In the six-plane, 64-iteration aligned kernels, all three systems measure normal DIVU at 4763–4767 CCK, worst-case DIVU at 5102, and DIVS at 5249–5257. These include shared loop and readback overhead. The old claim of 191 CCK early execution came from a defective beam conversion that doubled HPOS, plus unmatched launch phases. It is superseded, not a remaining 191-clock CPU defect. The corrected legacy table’s hardware 4891 versus Copperline 4886 is also phase-unmatched and must not be treated as a five-clock residual.

For the native 22-word/22-pixel STOP controls, hardware and WinUAE measure 83/84 CCK for D-only/AD copy, 105/106 for fill, and 127/128 for line mode. Before the source-phase correction Copperline measures 86/87, 108/109 and 130/131. Afterwards it measures 84/85, 106/107 and 128/129. The NOP phase is exact; the EXG phase remains +2. Results are identical with the same handler in chip RAM or ROM, excluding handler fetch placement as the explanation. All 896 IRQ trials agree on the saved exception PC. A later STOP fast-forward fix preserves the nearest device-event deadline in colour clocks instead of advancing the rounded instruction budget past it. With that fix, all 896 Copperline result records match the A500 packet byte-for-byte; WinUAE has zero IRQ-beam and saved-PC mismatches as well. The older +2 CCK odd-phase residual is closed for this synchronized kind-23 matrix. Copper-generated sources measure 261/262 CCK from launch on all three systems.

Changes made¶

  • MC68000 DIVU/DIVS flush internal computation clocks before their final prefetch and IPL poll. MULU/MULS keep their distinct existing sequence. Separate CPU-core bus-sequence tests cover operands, addressing modes, overflow and multiplier controls.

  • Normal and line blits have two internal startup clocks. BBUSY clears after E/the line tail, before the final destination flush. BLIT request readback is independently scheduled three clocks after E, even if the last D access stalls.

  • BLTPRI follows actual bus requests. Startup and first-D bubbles are available to the CPU; the unsupported extra startup fence was removed. The public compatibility query remains present and returns false.

  • A 68000 chip-memory transfer samples data at each granted slot before its trailing DMA clock. Byte, word, two-word long and the existing AGA wide-grant path have regressions. The accelerated CPU transfer path is unchanged.

  • STOP fast-forwarding now retains the earliest device-event deadline in CCK as well as the rounded CPU instruction budget. Idle device advancement is clamped to that deadline, including clocks already advanced by the CPU bus. The exact 896-row One ROM IRQ capture verifies all native and Copper-generated cases, including the formerly +2 CCK odd phase.

  • Normal BZERO visibility is delayed three CCK after the mathematical accumulator clears; fill’s extra idle phase (USE-D && !USE-C) adds one. An absolute Bus deadline continues after engine completion or DMA disabling. New starts reset it. Self-describing save states default the new field for older payloads and preserve an in-flight deadline; no format version changed. The line-mode visibility delay was reduced from one extra CCK to zero. This lowers BZERO mismatches in three of four line sweeps and leaves normal/fill results byte-identical, but line BZERO still needs a rule for its remaining input-dependent residual.

  • timing-test uses the corrected linear PAL beam metric. A two-byte, four-CPU-clock NOP replaces the old doubling instruction, preserving its size and timing cost. Its real committed binary is exercised by a regression. Screenshot references are emulator regression images, not hardware captures.

  • Default builds use the existing versioned vendor/m68k submodule. Root and frontend lockfiles resolve that checkout. Only workflows compiling/resolving Copperline fetch the first-level submodule; recursive fixture checkout is unnecessary for Copperline builds. The independent cputest runner continues using its own registry dependency.

Open work and measurement plan¶

1. Extend STOP coverage beyond the measured matrix¶

The scheduler-rounding issue is fixed for the synchronized kind-23 matrix. Keeping the earliest device-event deadline in CCK eliminates the prior +2 CCK odd-phase residual: all 896 Copperline records now match the A500 packet byte-for-byte, including IRQ beam and saved exception PC. The follow-up below extends phase and contention coverage beyond this exact test matrix.

For broader coverage, extend kind 23 with at least sixteen source horizontal phases, 0–31 NOP positions before STOP and an EXG phase flip. Keep native D-only, AD copy, descending fill and line controls, plus Copper BLIT/COPER/SOFT using the same IRQ levels and byte-identical RAM/ROM handlers. Add one-word/two-word sizes and deliberate final-D contention from bitplanes and Copper. Record the primary INTREQR read separately from the handler beam; do not let preliminary RAM reads disturb the timed observer. Acceptance: identical launch, IRQ beam and saved PC for every unambiguous pair, with the existing Copper 37/38-CCK parity tests and CIA STOP results preserved.

The three-CCK native source-phase adjustment is an inference from combined paths, not a direct measurement of Paula’s physical IPL pins. A logic analyzer on BLIT/INTREQ-related signals and CPU IPL would distinguish those internal stages if a later phase or contention sweep exposes a residual.

2. Finish line-mode BZERO isolation¶

The 15 October follow-up collected 25,636 validated new A500 records with One ROM, including the kind-33 repeat. See the detailed report and next-run handoff for source IDs, comparisons and the current acceptance results. The old single-region destination observer did not cover later D writes, which follow the C pointer in line mode; new probes scan both regions. Limit earlier zero-data statements accordingly.

Full-minterm, nonuniform-C and length sweeps isolate a texture-counter-wrap component using previous A/C holds. The narrowed correction applies only with USEB clear; extending it to B DMA introduces measured false clears. Other non-wrap effects remain: kind38 demonstrates a C-DMA-dependent flag change even with LF=cc, which ignores C in the ordinary minterm.

The next C-input follow-up is now measured; see the C-input and read-sequence report. Kind39 reproducibly isolates the first fetched C word, not the second word or BLTCDAT seed. Kind40 adds shift and A-data controls. Kind41 reveals variable flags between otherwise timing-identical runs, including post-busy samples. Do not turn those counts into a fixed mask lookup. The new report records the within-blit sequence control and the decision tree for retained state, CPU-bus activity, and ROM-versus-RAM execution.

The live-ROM backup is restored and hash-verified after each collection. Follow the latest report’s cleanup status and current-session backup; do not load an earlier backup over a newly configured live image.

3. Finish regression and scope checks¶

Re-run all optimized unit/integration and 45 screenshot tests, refreshing only the expected timing-test reference after reviewing its changed numeric table. Keep screenshot generation distinct from hardware trace comparisons. Repeat the measured observer sweeps if a change touches arbitration, sampling or the blitter sequencer. Check save/resume across BZERO and IRQ deadlines. Extend the phase matrix to bitplane/Copper/sprite/refresh contention, timer IRQs and scanline/frame boundaries. Measure host performance on an identical deterministic workload before claiming speed is unaffected; no controlled performance benchmark was completed here. AGA/other CPU accuracy requires appropriate hardware evidence rather than extrapolating this A500 result.

For an upstream submission, publish the m68k submodule commit before the parent gitlink, check source-archive/Homebrew packaging (GitHub archives omit submodule contents), and decide whether upstream accepts the path dependency or needs a published CPU crate release. These commits are local; no push was authorized or performed.
