Update, 16 October: new bus captures and reproduction controls do not reproduce the old kind39/kind42 C-dependent mismatches. The broader kind33 sweep still has BZERO differences. Preserve the observations below as dated evidence rather than treating every old mismatch as a current oracle.

Kind39 hardware result¶

Both 344-row hardware runs completed with zero timeouts/skips and passed strict checksum/source/descriptor checks. First packet SHA-256: 6eba2e3aa4b9a17b2d2311ca3b7c56d321a5252d03acfb18ff002764a052a7e2; repeat: 6eba2e3aa4b9a17b2d2311ca3b7c56d321a5252d03acfb18ff002764a052a7e2. The repeated observed fields differ by 0 BZERO flags, 0 end-beam readings and 0 memory observations. Both runs restored and verified the fresh backup and released SEL_C.

Copperline and WinUAE each disagree with hardware on 40/344 BZERO observations, with zero launch/end-beam, busy or memory differences. The effect requires USEB clear, USEC set and two pixels. For those controls, first C=0 clears BZERO, first C=ffff keeps it set; changing only the second C word does not reproduce the inhibition, nor do BLTCDAT-only seeds. Uniform first/second C=5555 inhibits the clear whereas aaaa does not. No individual one-hot first-C bit inhibits the clear. Thus the data dependency is in the first fetched C word and involves multiple bits; the one-hot-only result does not identify a single controlling bit.

Next kind40 adds one-cold words and LF=c0 A-shift tomography at BSH4, with independent DMA and one-pixel controls. This tests the effective B-word bit incidence rather than guessing from the B-only OR flag.

Planned kind40 tomography¶

At each selected BSH (initially 4), set A=8000, B=0, LF=c0 (A AND B, independent of C), Csecond=0 and BLTCDAT=0. Cross all 16 A shifts, first-C patterns 0/ffff/5555/aaaa and the 16 one-hot/16 one-cold patterns, and one/two pixels. This is 1,152 USEB-off/USEC-on rows. Add 192 rows covering the other USEB/USEC combinations with Cfirst=0/ffff. The 1,344-row ROM retains six-word descriptors and literal setup tables. Descriptor variant records BSH so comparisons cannot silently label a non-default shift as BSH4. Validate assembled size below 64 KiB, actual observer bytes and source identity before every hardware run.

First use BSH4 to reconstruct which A bits see a nonzero effective B input as each C bit is enabled/disabled; then repeat selected neighboring shifts only if this yields a stable pattern. B-only kind39 sees only an OR, which is why one-hot C words alone could not distinguish the participating bits.

Kind41 first hardware result and limit of the bit interpretation¶

Packet SHA-256 606eec64b87bdef264272c03bfd2763ba00c149e81ce3f9839d50a5793a11127; 2,584 valid records, zero timeouts/skips. Strict comparisons pass provenance and descriptors; each emulator differs on 299 BZERO observations and on zero launch/end-beam, busy or memory fields. The backup was restored and verified.

For Cfirst=0 and LF=cc, both A values keep BZERO set at the earliest read-end timestamp 18 CCK after the recorded launch beam, then show it clear at read-end timestamp20 and all later samples; one-pixel controls remain set. These are software observation timestamps, not a claim that the internal flag changes at exactly20 CCK. The DMACONR read precedes its beam timestamp. Phase kernels have launch positions4242/4243, so phase and launch alignment must remain separate when interpreting the boundary.

For Cfirst=ffff, A=8000, two pixels, phase 1/delay 2 reads clear at endpoint23 CCK, but later trials read set. Cold-bit14 with A8000 reads clear at most late positions, set at delays15, then clear again at delay16. These are separate blits; this is not evidence that a single blit’s flag actually reasserted. It disproves using this sweep as a simple monotonic transition or fixed C-bit mask without additional controls. An exact repeat is running.

Next compact kind42: eight consecutive DMACONR reads into D0–D7 within one blit, with no intervening stores, followed by a MOVEM of all samples. Cross early versus post-busy-clear observation, Cfirst0/ffff/fffe/bfff/feff, A0/8000 and eight repeats. This tests within-run readout changes versus persistent state or CPU-bus/history effects between independent trials. A static data rule or BSH mask table must not be added from these data.

Next-step decision tree after the within-blit control¶

  1. If post-busy sequence reads change within one blit, investigate readout bus influence or non-latched line-mode status. Repeat from slow RAM with the same opcodes, separating One ROM instruction serving from chipset effects; preserve exact per-mode cycle/beam provenance.

  2. If each sequence is stable but independently launched trials differ, prime all normal-mode A/B/C holds before every trial, then compare forward/reversed/randomized preset order and controlled repeats. Kind34 only primed B and does not rule out other retained state.

  3. Run a Copper-launched blit while the CPU is stopped, waking by a separately measured IRQ to read BZERO. Compare an equal-timeline active-CPU observer to isolate CPU-bus activity during the blit.

  4. Only after those controls, collect held-out C combinations and full minterm closures at BSH4/6/8. A state-based datapath/visibility rule must predict both final flags and the early read matrix, and must preserve timing, memory and the already-matched normal/fill/IRQ sets.

  5. Do not use a per-BSH mask lookup or optimize against non-repeatable rows. Extend the earlier wrap correction only when new capture sets have no regressions; rerun optimized core tests, goldens and a controlled performance workload if core code changes.

Prioritize CPU-quiet Copper/STOP launch, controlled equal-cycle bus traffic and full A/B/C priming, then ROM-versus-slow-RAM execution. The already-committed wrap fix is independently strengthened by the BSH0 controls; its remaining 58 rows include behavior outside the corrected path.
