A500 BZERO bus validation, 2026-10-16

Scope and evidence¶

Measurements use the same physical PAL A500 (512 KiB chip, 512 KiB slow, ECS Agnus, OCS Denise), One ROM Fire 40 A and Rigol MHO98 with PLA2216. CH1 is disconnected; these are digital captures. Capture files and ROM images remain local in amiga-hardware-probes/captures/ and build/. No additional Copperline behavior change is justified by the results below.

The broader kind33 sweep still differs: its two new 1,024-record captures have 36/37 BZERO-word differences from current Copperline and 48/49 from WinUAE. Every other recorded field matches. Targeted controls are required before changing the existing line-wrap model; see below.

The earlier kind42 result remains valid as a description of that capture, but its mismatch has not reproduced on the current powered-on setup. Do not treat its 896 differing BZERO samples as a currently reproducible acceptance target.

Independent digital wiring check¶

A continuous diagnostic ROM reads custom offsets 002,004,008,010,020, 040,080,100 in order, with three NOPs after each read. It disables DMA and masks interrupts. This independently exercises every probed address bit A1 through A8 instead of relying on Kickstart reads whose addresses share several high bits.

build/scope_address_a1_a8_20261016/ raw ROM SHA-256: a6302bc421abb8534bb6f379efe476b4c7fa1af7a8e5444437a850fcea6fe99d. captures/bzero-scope-2026-10-16/address-walking-full.bin contains 70 qualified read windows, all in the expected repeating order. Qualification requires AS, Gary REGEN, UDS and DTACK active together, with stable R/W and address. The wiring and decoder pass this check.

With analog channels disabled, 20 microseconds/division and a requested one-million-point acquisition, the exported LA record contains 250,000 packed digital samples. D0’s rising-edge period averages 140.969 samples, consistent with about 1 ns per digital sample using the nominal PAL CPU clock as reference. The file’s 250 ps increment is unsuitable for LA timing; the declared payload size is also overstated. Analysis uses actual payload length and captured clock edges. This reference-derived scale is not an independent absolute timebase calibration.

Continuous line captures and positive control¶

Three small diagnostic ROMs repeatedly restore the same two-pixel line configuration, launch it, and read DMACONR eight times consecutively from RAM code. Unlike kinds44/45, they do not synchronize to a frame phase. The archive names are build/scope_bzero_c0000_b0000_v4_20261016/, scope_bzero_cffff_b0000_v4_20261016/, and scope_bzero_c0000_bffff_v4_20261016/. B DMA is disabled in all three; the last sets BLTBDAT to ffff as a nonzero-result positive control.

Qualified DMACONR windows show BZERO high for the zero-B controls with first C either zero or ffff. With B=ffff, D13 settles low on subsequent reads. This rules out a D13 input stuck high and shows actual bus values, rather than relying only on the ROM’s exported status words.

Several windows contain a transition after DTACK is already active, consistent with data settling during a read. The decoder records first and last levels plus every transition; it does not label such a window stable or silently pick its midpoint. These observations alone do not establish the exact 68000 data-sampling instant or an internal flag edge. The first read observes busy, subsequent reads observe completion.

Controlled CPU bus write¶

Kind46 tests a narrower hypothesis: a CPU data transfer immediately after launch influences the extra line-mode BZERO evaluation. It crosses all 16 A shifts with six write words (0000,ffff,2000,0800,2800,d7ff), chip RAM 18000 versus slow RAM c01000, and eight repeats (1,536 records). Each trial uses A=8000, B=C=0, B shift0, LF=ca, B DMA off and two pixels. The observer writes BLTSIZE, executes MOVE.W D3,(A3) to the selected scratch address, then performs eight consecutive DMACONR reads. The opcode and destination remain identical when comparing values within one region. All source words are restored explicitly, including the second C word. After completion, both destination words are recorded separately.

The region index temporarily occupies the descriptor’s phase field. That field is held at zero through both beam alignment stages, then restored before the record is finalized. Preflight confirms identical launch phase for both regions. The controller saves/restores A3, which the outer measurement loop uses as its descriptor pointer.

Archive build/line-c-bus-data-kind46-v2/ source ID: 5a9cfc28ee9c17a620d259ec73a8b05ce9f0b5f45c72dc26a8f694747dce6317; raw ROM SHA-256: 3d6fb876bac15bebdac4e6725524ac38bf939f925dd1571d887d62078de37256. Both emulator preflights completed all records, with identical launch and subsequent beam fields, zero destination readbacks throughout, and no timeouts or skips. Copperline clears all eight BZERO samples in every trial; WinUAE sets all of them. Every sample pair differs only by 2000. CCP also verifies zero A/B/C source memory and the final d7ff word at both scratch addresses. Those final scratch checks do not independently verify every preceding write value on hardware.

The A500 completed all 1,536 records with no skips/timeouts. Packet SHA-256: 303a2776216993689ef8c95c5f32afab05abd20f56c898bee44a1fb5332cee3f. Every destination readback is zero, and all recorded beam fields match both emulator preflights. BZERO is set only for A shifts 2/4: 192 records, or 1,536 sample words. It is clear for the other 1,344 records. Each case is invariant across all six CPU write values, both RAM regions, all eight repeats and all eight samples. Copperline therefore falsely clears 1,536 sample words; WinUAE falsely sets 10,752. This specific CPU write-value/ destination control does not explain the mask. Other CPU traffic phases have not thereby been ruled out.

Two further continuous diagnostics hold the A shift field at zero and write ADAT=2000 or 0800 instead. Both leave BZERO set, matching ADAT=8000 shifted by 2 or 4 respectively. Captures are bzero-a2000-ash0-bsh0-ca.bin and bzero-a0800-ash0-bsh0-ca.bin. This supports dependence on the effective A bit position rather than only on the A-shift register field. The next matrix should include nonzero-B output-word controls to verify the alternative ADAT inputs independently; do not turn this incidence map into an unexplained constant.

Next controls¶

  1. Repeat any new flag differences before inferring a rule. The selected normal-mode zero/nonzero A/B/C histories have been tested and matched; further state controls need a distinct hypothesis.

  2. Cross all 16 one-hot ADAT words with A shifts 0/2/4, B data 0/ffff, one/two pixels and eight repeats in a checksum-protected One ROM suite. Keep C zero and B DMA off, record both actual output words and the eight early DMACONR reads. B=ffff controls must prove the intended shifted A words reach memory. This separates effective bit position, counter state, nonzero data and the inter-pixel wrap evaluation.

  3. Cross a reduced discriminating set with A-data/control-register write order, controlled prior line operations and early/postbusy observers. Only then extend full minterm closures and the B-DMA path. Retain the existing within-case repeat and exact timing/memory checks.

  4. If the old C-dependent mismatch remains absent, distinguish power-on state and probe loading with a controlled physical comparison. The owner confirms a power-off occurred, but both factors changed between sessions. Plan the reset/loading sequence before asking for wiring changes; do not fit the older non-reproducing packet.

  5. Accept a core correction only when a repeatable state/datapath rule predicts held-out inputs and preserves existing normal, fill, IRQ and accepted line-wrap results.
