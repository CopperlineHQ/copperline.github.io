Copperline 0.21.0: spectators, four controllers and desktop fixes

Copperline 0.21.0 is out. Netplay now has room for an audience, local multiplayer can use four gamepads, and the desktop does less work between finishing an Amiga frame and putting it on screen.

There are also fixes for native file pickers and shutdown, plus two changes to the default machine configuration that are worth checking before you upgrade.

Invite people to watch

A host can admit up to eight spectators on desktop or in the browser. The spectator invitation is separate from the player invitation, so a watcher cannot take player 2's place.

Spectators can join a game in progress. They receive the host's setup and media, then replay the confirmed input history as fast as their machine allows until they catch up. They follow a few frames behind the players and receive synchronized floppy changes too. There is no video stream: each spectator runs and checks its own emulated Amiga, so the longer a game has been running, the longer a new spectator takes to catch up.

On the desktop, choose the spectator count in the Netplay settings and generate a spectator invitation. In the browser, Host game supplies a spectator link with copy, share and QR controls. Open that link and choose Watch game. Leaving a spectator session does not interrupt the players.

A game still has two active players. Everyone needs the same Copperline build, desktops connect only to desktops and browsers only to browsers, and mixing operating systems or browser engines has not been verified yet. See the netplay guide.

Four local controllers

The desktop now reads four independent gamepads through the Amiga's two game ports and the parallel-port joystick adapter. Choose Multitap (4 joysticks) in the launcher, set both native ports to Joystick and use gamepad input mode. The cursor keys and numeric keypad can fill spare player slots. Disconnecting one pad leaves the others assigned to their players.

The RetroArch core exposes the extra sockets as ports 3 and 4. Select Parallel-port joystick (multitap) for those ports in Quick Menu → Controls. This is local four-player support for games such as Super Skidmarks; Copperline's own netplay remains two-player. The desktop controller guide and libretro guide cover setup.

Display work and desktop fixes

Presentation reuses TV-aperture calculations and repeated rows, draws eligible pictures on the GPU, and moves upload and presentation work to a worker thread. The core also avoids redundant DMA decoding and Copper WAIT checks. None of this changes emulated timing; it only reduces the work the host does.

Video Settings → VSync now takes effect immediately. It is on by default; turning it off can reduce latency where the platform supports it, at the cost of tearing. PAL output still has an uneven cadence on a display whose refresh rate does not match. Frame scheduling on Wayland is also improved.

For high-density displays, [display] hidpi_texture = false reduces texture and copy work. Integer scaling keeps its appearance; smooth scaling may show differences in fine interlaced detail. Captures are unaffected.

  • On Windows, automatic renderer selection now tries accelerated OpenGL before falling back to a CPU renderer. An explicit backend choice is still honoured.
  • Windows file pickers no longer freeze the window. macOS uses sheets, avoiding a macOS 27 crash when a native picker is resized.
  • Closing the window or quitting on macOS no longer deadlocks while the presentation worker releases the window.
  • Starting Copperline from Windows Explorer no longer leaves a console window open, and the executable now has its icon and version resources.
  • PCMCIA gets its own menu, and the Netplay enable control now matches the stepper controls around it.

RetroArch state buffers are now sized for the loaded machine: a typical A500 floppy session reserves about 14 MiB instead of 64 MiB, and an A1200 about 18 MiB. This reduces memory use and per-frame checksum work. Larger configurations need more space.

Before upgrading

  • Clipboard sharing is off by default. The extra autoconfig board changes the guest's memory layout and caused a hang in Lotus Esprit Turbo Challenge. Enable it with --clipboard or [clipboard] share = true if you want it. A setting you saved explicitly still applies.
  • The CD32 FMV slot starts empty. Fitting the module changed memory layout and boot timing even for games that did not use it, including Kang Fu's intro. Choose Fit in the launcher's FMV row or set top-level fmv = true to use the bundled open ROM. A named fmv_rom still fits that ROM.
  • Recreate RetroArch save states after updating the core. The core checks a build fingerprint that includes the release version. Desktop states keep the chunked format introduced in 0.20; states from 0.19 and earlier still cannot be loaded. Disk images and saves made inside games are unaffected.

New regression tests boot copperhf.device under Kickstart 1.3 with a compatible FastFileSystem. The reported crash came from a newer FastFileSystem binary that needs libraries Kickstart 1.3 does not have; the documentation now explains what to check. Dependency updates include the rustls fix for RUSTSEC-2026-0285.

Thanks to Lee Hobson for the file-picker and menu work, Simon Dick for the copperhf investigation and documentation, and everyone testing and supporting Copperline.
